Config files in. Body of Evidence out.

boecheck scans Kubernetes, Helm, Terraform and Ansible files, reports what breaks a control, and writes the evidence control by control with the file and line. It also turns an SLO file into burn-rate alerts and a runbook.

git clone https://github.com/gerardrecinto/boecheck.git && cd boecheck && go run ./cmd/boecheck scan examples/bad

 

Try it in your browser

The same Go code as the CLI, compiled to WebAssembly. Paste Kubernetes YAML or Terraform. Nothing leaves the page.

NIST SP 800-53r5Every check names the controls it gives evidence for. The Body of Evidence groups results by control, with file and line.


NIST SP 800-207Checks are also mapped to the zero trust tenets: mTLS (tenet 2), per-session access (3) and enforced authorization (6).


HIPAA Security RuleEncryption at rest, transmission security, access control and retention checks map to 45 CFR 164.312 and 164.316.


Kubernetes and HelmPod security, pinned images, limits, probes, default-deny NetworkPolicy. helm template | boecheck scan - is part of the e2e run.


IstioChecks for namespace-wide STRICT mTLS and for an AuthorizationPolicy that is not allow-all. Mesh-wide policy in istio-system counts. Lab only, see meshdoctor.


TerraformOpen security groups, S3 encryption and public access, encrypted databases and volumes, log retention.


AnsiblePlays with TLS validation turned off or plain-text credentials.


HashiCorp VaultDetects Vault agent injection as evidence for IA-5 and flags secrets committed in manifests and playbooks. No Vault server is run here.


SLIs, SLOs, alertingAn SLO file becomes multi-window burn-rate rules. promtool checks the rules and a unit test proves the page alert fires at a 2% error rate and stays quiet at 0.05%.


Run books and SOPsboecheck runbook writes the budget math, the alert table and the response steps for each SLO.


Bash and PythonThe e2e is Bash with set -euo pipefail. Python is covered by my Qualcomm work, not this repo.

SLO file in, alerts and runbook out
Burn rate is the share of budget spent times the window, divided by the look-back. Over 30 days: 2% in 1 hour is 14.4x, 5% in 6 hours is 6x, 10% in 3 days is 1x.


service: checkout
slos:
  - name: availability
    objective: 99.9
    window: 30d
    errors: sum(rate(http_requests_total{job="checkout",code=~"5.."}[$WINDOW]))
    total: sum(rate(http_requests_total{job="checkout"}[$WINDOW]))

$ boecheck slo slo.yaml     # Prometheus rules: 5 recording rules, 3 alerts
$ boecheck runbook slo.yaml # RUNBOOK.md with budget math and response steps

Limits


This reads files. It shows configuration, not how a system runs, and it is not an assessment: an assessor decides what counts as evidence. The mapping from checks to controls is my reading, not an official crosswalk. The Terraform scanner finds resource blocks and checks their text; it does not evaluate variables, modules or count, so it can miss and can be fooled. Ansible checks apply to plays with hosts or tasks. Istio and Vault are checked as config only; no mesh or Vault server is started here. It covers a small set of controls, not a full baseline. I hold no clearance and have not run an A&A package; this is a tool I built to learn the shape of one.
